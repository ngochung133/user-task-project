# Spring Boot REST API practice roadmap

Researched 2026-11-01 against the project's `pom.xml`: Spring Boot **4.1.1**, Java **25**, Spring MVC, Data JPA/MySQL, Validation, Security, and an OAuth2 Authorization Server starter. Boot's current system requirements cover Java 25. The project already has the Boot 4 feature-specific MVC, JPA, Security, and Validation test starters. [Spring Boot system requirements](https://docs.spring.io/spring-boot/system-requirements.html) · [Spring Boot testing](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html)

## Suggested sequence

1. **Finish one small CRUD API.** Implement `POST /users`, `GET /users/{id}`, a paged `GET /users`, `PUT /users/{id}`, and `DELETE /users/{id}` with request/response DTOs, meaningful HTTP statuses, and a service boundary. Use `@Valid` on request DTOs; Spring MVC distinguishes request-body validation (`MethodArgumentNotValidException`) from direct method-parameter validation (`HandlerMethodValidationException`). Choose one consistent error contract. Spring's `ProblemDetail` and `ResponseEntityExceptionHandler` support RFC 9457 responses; Boot also has `spring.mvc.problemdetails.enabled` for built-in MVC exceptions. [MVC validation](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-validation.html) · [MVC error responses](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-rest-exceptions.html)

2. **Test at three levels.** Use `@WebMvcTest(UserController.class)` with `MockMvc` and `@MockitoBean` for request mapping, JSON, validation, error responses, and security rules. Use `@DataJpaTest` for repository queries and JPA mappings; it scans entities/repositories and rolls back transactions. Then add a few `@SpringBootTest` tests for full request-to-database behavior. For MySQL-specific behavior, run MySQL with Testcontainers and `@ServiceConnection`; this needs `spring-boot-testcontainers` plus Testcontainers dependencies. The existing context-load test alone does not exercise the API. [Spring Boot test slices and full tests](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html) · [Testcontainers service connections](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html)

3. **Make the schema repeatable.** Add versioned migrations and run them against the same MySQL version in local development and integration tests. Boot supports Flyway and Liquibase; for Flyway with MySQL, its guide calls for the Flyway starter plus `org.flywaydb:flyway-mysql`, with scripts under `classpath:db/migration` by default. Avoid mixing a migration tool with `schema.sql`/`data.sql`. [Spring Boot database initialization](https://docs.spring.io/spring-boot/how-to/data-initialization.html)

4. **Learn configuration and secrets.** Put environment-specific settings in profile-specific files, but inject credentials at runtime through environment variables or mounted configuration trees such as `configtree:/run/secrets/`. Bind related settings with `@ConfigurationProperties`; test at least a local and a production-like profile. Boot documents property precedence and profile activation. [Externalized configuration](https://docs.spring.io/spring-boot/reference/features/external-config.html) · [Profiles](https://docs.spring.io/spring-boot/reference/features/profiles.html)

5. **Secure the API after its contract is stable.** Start with a `SecurityFilterChain`, password encoding, and tests for anonymous/authorized requests. If an external identity provider issues tokens, use the OAuth2 **Resource Server** path: it verifies bearer JWTs using an issuer or JWK set URI, and can validate an expected audience. The Authorization Server starter already in this POM serves a different role: issuing tokens. Only build that side if token issuance is itself a learning goal. Prefer Spring Security's JWT validation path over writing a token parser/filter from scratch. [Boot resource-server configuration](https://docs.spring.io/spring-boot/reference/security/oauth2.html) · [Spring Security JWT resource server](https://docs.spring.io/spring-security/reference/7.0/servlet/oauth2/resource-server/jwt.html) · [Authorization Server getting started](https://docs.spring.io/spring-security/reference/7.0/servlet/oauth2/authorization-server/getting-started.html)

6. **Document and operate it.** For OpenAPI/Swagger UI on Boot 4.1.x, springdoc's own compatibility table lists **springdoc 3.1.x–3.2.x**; its current guide shows `org.springdoc:springdoc-openapi-starter-webmvc-ui:3.2.0` (or `...-webmvc-api` for JSON only). Verify `/v3/api-docs` and the UI with this app's security configuration. Spring REST Docs is an official Spring alternative for test-generated API documentation, though it does not itself promise OpenAPI output. Add Actuator for health and metrics, then Micrometer observations/tracing if useful. Expose only the management endpoints needed; a custom `SecurityFilterChain` makes actuator access rules your responsibility. [springdoc compatibility and setup](https://springdoc.org/) · [Spring REST Docs](https://docs.spring.io/spring-restdocs/) · [Actuator endpoints](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html) · [Observability](https://docs.spring.io/spring-boot/reference/actuator/observability.html)

7. **Ship the same build that CI checks.** Run `mvn --batch-mode verify` on every change with JDK 25 and a Maven dependency cache; include the MySQL container tests in this gate. Package with the existing Spring Boot Maven plugin as an executable JAR, then optionally build an OCI image with `spring-boot:build-image`. For future Boot upgrades, read the upgrade notes for every intervening release and rerun the full test suite, especially the MVC/security/OpenAPI checks. [GitHub Actions Maven guide](https://docs.github.com/en/actions/tutorials/build-and-test-code/java-with-maven) · [Spring Boot build guide](https://docs.spring.io/spring-boot/how-to/build.html) · [OCI image packaging](https://docs.spring.io/spring-boot/maven-plugin/build-image.html) · [Upgrading Spring Boot](https://docs.spring.io/spring-boot/upgrading.html)
